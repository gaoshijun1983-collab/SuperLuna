# macOS Codex 宿主续行能力核查

核查日期：2026-08-11

## 结论

当前 macOS Codex 宿主没有向 SuperLuna 插件暴露可确定使用的任务结束拦截或同一 turn
强制续行接口。因此，控制器返回的 `continuation_required=true`、`next_action` 和
`turn_completion_allowed=false` 只能检测任务提前结束，不能阻止宿主接受 final。

这是一项平台阻塞，不是 SuperLuna 控制器、等待定时检查或 Chat 回复读取故障。不得用额外
heartbeat、第二个协调任务、多个等待项或无条件轮询伪装为已经解决。

## 已核查的宿主表面

当前 Codex 提供给任务的 App 能力包括任务创建、读取、等待、发送消息、交接、固定、归档、
标题、页面导航和自动任务管理。可见能力中没有：

- 插件级 turn 结束钩子；
- 活动工作流状态下拒绝 final 的拦截器；
- 控制器返回下一动作后保证同一 turn 继续的宿主 API；
- 等价且不引入第二调度器的原生续行机制。

对本机 ChatGPT App 资源和本地 Codex 配置做的定向检索也没有发现可供插件调用的公开接口。
未暴露给插件的宿主内部实现不能作为产品能力使用。

## 产品影响

- 本地控制器测试、`selftest` 和 `closure-check` 仍只证明本地确定性合同。
- Windows 真实 1/3 结果不得提升为通过。
- 冻结候选连续真实项目周期仍为 0/10。
- Public Beta 必须继续为 `false`。
- 在宿主提供原生执行拦截前，不能声称“回复吸收后必定在原任务同一 turn 自动继续”。

## 重新评估条件

只有出现可由插件实际调用并可复现验证的宿主能力时，才重新开启该方向的代码开发。届时先做
隔离验证，证明活动状态无法结束 turn，再恢复同一项目、同一固定 Chat 的零干预三轮测试。
